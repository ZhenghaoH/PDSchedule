# GitHub 上传更新计划

## 目标

将当前项目更新上传到指定 GitHub 仓库，保留本地改动记录，并避免误推到错误远程仓库。

本次上传目标为 `https://github.com/BJTU-ANT/FlexPD`，不覆盖主分支，而是在该项目中创建一个测试用途的新分支来保存当前整个项目版本。

## 当前状态判断

- 当前本地仓库已经配置远程 `origin`，地址为 `https://github.com/BJTU-ANT/FlexPD.git`。
- 当前本地仓库还没有有效的 `HEAD` 分支，`git branch --show-current` 无法解析当前分支。
- 当前文件大多处于未跟踪状态，说明需要先完成首次提交或重新建立本地分支。

## 推荐流程

1. 确认目标 GitHub 仓库地址。
2. 如果目标不是当前 `origin`，先更新远程地址。
3. 创建本地测试分支，命名为 `test/20260420`。
4. 检查 `.gitignore`，避免提交缓存、虚拟环境、模型权重、大数据文件等不应上传内容。
5. 使用 `git add .` 添加整个项目快照。
6. 创建提交。
7. 推送到目标 GitHub 仓库的新分支，不直接推送到主分支。

## 推荐分支命名

建议使用：

```text
test/20260420
```

原因：

- `test/` 前缀能明确表示该分支是测试用途。
- `profile-preanalysis` 描述当前版本主要方向。
- 日期便于后续区分多个测试版本。

## 验证

- `git status` 显示工作区符合预期。
- `git remote -v` 指向正确 GitHub 项目。
- GitHub 页面能看到新的测试分支。
- 主分支没有被覆盖或强制更新。
- 新分支中包含当前本地项目的完整测试版本。
