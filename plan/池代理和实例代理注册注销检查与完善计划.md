# 池代理和实例代理注册注销检查与完善计划

## 检查目标

确认并完善以下链路：

1. 池代理 Gateway 在启动时是否向全局调度器注册。
2. 池代理 Gateway 在退出时是否向全局调度器注销。
3. 实例代理 Instance 在运行时是否向池代理注册或上报。
4. 实例代理 Instance 在退出时是否向池代理注销。

本计划优先考虑最小化修改范围，避免新增无必要的抽象层。

## 当前检查结论

### 1. 池代理启动时会向全局调度器注册

已实现。

Prefill Gateway：

- `core/lifespans/gatewayP.py`
- startup 中调用 `prefill_compute_register()`
- 注册接口：`POST /prefill_pool/register`
- 注册成功后保存 `pool_id`

Decode Gateway：

- `core/lifespans/gatewayD.py`
- startup 中调用 `decode_compute_register()`
- 注册接口：`POST /decode_pool/register`
- 注册成功后保存 `pool_id`

### 2. 池代理运行时会向全局调度器心跳上报

已实现。

Prefill Gateway：

- `prefill_compute_update()`
- 上报接口：`POST /prefill_pool/update`

Decode Gateway：

- `decode_compute_update()`
- 上报接口：`POST /decode_pool/update`

### 3. 池代理退出时尚未向全局调度器注销

未实现。

当前两个 lifespan 里都只是停止线程，并保留 TODO：

- `core/lifespans/gatewayP.py`
- `core/lifespans/gatewayD.py`

现状：

```python
# TODO：向全局调度器注销
```

控制器侧也没有对应 unregister 路由：

- `core/routers/controller.py` 只有 register/update。
- `core/handlers/controller/update.py` 只有注册和心跳更新 handler。
- `store/controller/pool_manager.py` 只有 register/update/touch，没有 unregister。

目前全局调度器主要依赖 `last_updated` 超时判断离线，不是主动注销。

### 4. 实例代理运行时会向池代理上报，但不是显式注册

部分实现。

Instance 运行时：

- `core/lifespans/instance.py` 启动 `metric_update_loop_task`
- 周期调用 `coord/instance/up_store.py` 的 `metric_update()`
- 上报接口：`POST /instance/update`
- 上报字段包含 `report_label = host:port`

Gateway 侧接收：

- `core/handlers/gateway/prefill/update.py`
- `core/handlers/gateway/decode/update.py`

但这里不是显式注册。

当前实例表来源：

- Gateway 启动时，`GatewayStoreManager.set_config()` 会把配置里的实例地址写入 `_instance_table`。
- `/instance/update` 收到上报时，只接受已经存在于 `_instance_table` 的 `report_label`。
- 如果实例不在表中，会返回 404。

因此，当前语义是：

- 配置预注册 instance。
- instance 运行时通过心跳更新状态。
- 不支持未知 instance 主动注册。

### 5. 实例代理退出时尚未向池代理注销

未完整实现。

`coord/instance/up_store.py` 中已有：

```python
def close_instance_pair():
    endpoint = "pd/close"
```

该函数只会调用池代理的 `/pd/close`，目前作用是移除配对关系：

- `core/handlers/gateway/prefill/pair.py`
- `core/handlers/gateway/decode/pair.py`
- `manager.remove_from_link_table(instance)`

它不会从 Gateway 的 `_instance_table`、`_prefill_objs`、`_decode_objs` 中删除该 instance。

`core/lifespans/instance.py` shutdown 中也仍是 TODO：

```python
# TODO：向全局调度器注销
```

所以实例退出时不会真正从池代理注销，只会停止心跳。

## 最小完善方案

### 1. 全局调度器增加池注销能力

修改文件：

1. `store/controller/pool_manager.py`
2. `store/controller/network.py`
3. `core/handlers/controller/update.py`
4. `core/routers/controller.py`
5. `coord/gateway/up_store.py`
6. `core/lifespans/gatewayP.py`
7. `core/lifespans/gatewayD.py`

新增最小能力：

- `PoolManager.unregister_Pool(pool_type, pool_id)`
- 删除 `_pools[type][pool_id]`
- 删除对应 `_ip_index`
- 同步删除相关 Network 连接

新增接口：

```text
POST /prefill_pool/unregister
POST /decode_pool/unregister
```

请求体：

```json
{
  "pool_id": 1
}
```

Gateway shutdown 时调用：

- Prefill 调 `prefill_compute_unregister()`
- Decode 调 `decode_compute_unregister()`

如果 controller 已退出或网络失败，只记录 warning，不阻塞进程退出。

### 2. 池代理增加实例注销能力

修改文件：

1. `store/gateway/manager.py`
2. `core/handlers/gateway/prefill/update.py`
3. `core/handlers/gateway/decode/update.py`
4. `core/routers/gatewayP.py`
5. `core/routers/gatewayD.py`
6. `coord/instance/up_store.py`
7. `core/lifespans/instance.py`

新增最小能力：

- `GatewayStoreManager.unregister_instance(instance_ip)`
- 从 `_instance_table` 删除该实例。
- 从 `_prefill_objs` 和 `_decode_objs` 删除该实例。
- 从 `_link_table` 删除与该实例相关的配对。

新增接口：

```text
POST /instance/unregister
```

请求体：

```json
{
  "report_label": "172.18.0.169:7001"
}
```

Instance shutdown 时调用：

- `instance_unregister()`
- 目标：`http://{storage.gateway}/instance/unregister`

如果 gateway 已退出或网络失败，只记录 warning，不阻塞进程退出。

### 3. 是否需要实例启动时显式注册

为最小化修改范围，建议暂不新增 `/instance/register`。

原因：

- 当前 Gateway 启动时已经通过配置池预置实例表。
- Instance 运行时的 `/instance/update` 能完成状态刷新。
- 本次需求更关键的是退出注销，补 `/instance/unregister` 即可闭环。

如果后续需要支持动态扩容未知实例，再单独增加 `/instance/register`。

## 修改后预期行为

### 池代理 Gateway

启动：

1. Gateway 向 Controller 注册。
2. Controller 返回 `pool_id`。
3. Gateway 周期心跳上报。

退出：

1. Gateway 停止心跳线程。
2. Gateway 向 Controller 发送 unregister。
3. Controller 删除该 pool 和相关网络连接。

### 实例代理 Instance

启动：

1. Instance 周期向 Gateway `/instance/update` 上报。
2. Gateway 更新对应 instance 的负载状态。

退出：

1. Instance 停止心跳线程。
2. Instance 向 Gateway `/instance/unregister` 发送注销。
3. Gateway 删除 instance、可用列表和相关配对关系。

## 风险点

1. 如果 shutdown 时目标服务已先退出，注销请求会失败；应记录 warning 后继续退出。
2. 如果删除 pool 时未同步删除 network，调度器可能保留脏链路；因此需要补 NetworkManager 的相关删除方法。
3. 如果删除 instance 时未同步删除 link_table，后续配对可能引用已退出实例；因此 instance 注销需要同时清理 link_table。
4. 当前实例启动仍依赖 Gateway 预置实例表，不支持未知实例动态注册。这是本次最小方案的有意取舍。

## 验证方式

1. 启动 Controller、GatewayP、GatewayD，确认池注册成功。
2. 关闭 GatewayP，确认 Controller 中对应 Prefill pool 被删除。
3. 关闭 GatewayD，确认 Controller 中对应 Decode pool 被删除。
4. 启动 InstanceP/InstanceD，确认 `/instance/update` 正常。
5. 关闭 InstanceP/InstanceD，确认 Gateway 中对应 instance 被删除，相关 link 也被清理。
6. 在 Controller 控制台执行 `show pool_id`，确认注销后不再显示已退出 pool。
